# Отдельная установка SL OVERLAP

Это отдельный PAPER-вариант репозитория `Mihail9990/Simylator`, ветка
`sl-overlap-recovery`. Это не обновление обычного симулятора из `main`.

1. Скачайте и полностью распакуйте ZIP ветки `sl-overlap-recovery`.
2. На новом Windows-сервере с Python 3.13 x64 и MT5 запустите `START_INSTALLER.bat`.
3. «Установить / обновить» разрешает только `sl-overlap-recovery`, получает SHA
   коммита и скачивает архив этого точного SHA. Перехода на `main` нет.
4. Стандартная папка: `%LOCALAPPDATA%\AI_IMPULS_PAPER_SL_OVERLAP`.
   Настройки, SQLite, журнал, окружение Python и сохранённые версии находятся
   только внутри неё. Не передавайте через `--root` папку прежнего симулятора.
5. Заполните настройки MT5 и пароль панели; `enable_trading` оставьте `false`.
   Запуск процесса и открытие панели выполняются отдельно после установки.
6. Для следующих обновлений используйте установленный `START_PAPER.bat`.
   Обновление сохраняет настройки и SQLite без пересчёта истории, готовит резервную
   копию и не запускает симуляцию. Активный процесс нужно остановить.
7. Для телефона используйте `SETUP_PAPER_PHONE_HTTPS.bat`: его стандартный
   корень также указывает на SL OVERLAP. Нужны предусмотренные подтверждения
   изменений HTTPS-службы/firewall. Порт панели остаётся 8766, HTTPS 443;
   вариант рассчитан на отдельный сервер, не на совместный запуск на этих
   портах с обычным симулятором.

Установщик, откат, запуск из управляемой установки и настройка HTTPS проверяют
отдельную идентичность варианта. Архив обычного `main`, обычный каталог
установки и старые несовместимые релизы отвергаются без переключения кода.
Не переименовывайте и не удаляйте маркеры ради обхода проверки.

Проверки установки здесь выполняются офлайн с подставными GitHub-ответами и
архивами. Это не проверка Windows, фактической загрузки с GitHub, MT5 или TLS
на сервере пользователя.

## Обновление при ручной сверке или неизвестном исходе команды

Установщик заменяет только код. RECOVERY, текущая фаза, UNKNOWN-команды и
история исполнений больше не определяют доступность обновления/отката:
они копируются без исправления, пересчёта или удаления. Перед переключением
создаётся резервная копия SQLite. Проверки самого файла SQLite, формата PAPER,
правильной папки и совместимости пакета сохраняются. Обновление не означает,
что спорная история исправлена: это проверяет запущенный симулятор.

Если старый установщик показывает «нужна проверка истории или неизвестных
исходов команд», распакуйте свежий ZIP и откройте `START_INSTALLER.bat` именно
из него, затем выберите «Установить / обновить». Старое окно использует старую
проверку до своего перезапуска. Не удаляйте базу.

## Остановка процессов

«Остановить процессы PAPER» доступна и в новом окне установщика. Она завершает
основные процессы именно этой установки и её сборщики котировок, в том числе
оставшиеся после прежних запусков. Сначала передаётся запрос штатной остановки;
оставшиеся подтверждённые процессы завершаются принудительно. Это не закрывает
виртуальные позиции и не удаляет ожидающие ордера из SQLite.

Принадлежность определяется по точным путям этой установки, аргументам запуска
и идентичности процесса, а не по имени `python.exe`. MT5, другие установки,
окно установщика и отдельно установленная HTTPS-служба не завершаются.
Если Windows не позволяет подтвердить владельца или завершение процесса,
показывается ошибка, а не сообщение об успешной остановке.

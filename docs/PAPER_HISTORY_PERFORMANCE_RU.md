# История PAPER: производительность без сброса состояния

Изменения применяются только к PAPER. Реальные ордера не отправляются.

- Поиск подтверждений ордеров и сделок использует временные индексы текущего снимка вместо повторного полного просмотра истории для каждого ордера. Приоритет подтверждений и проверки позднего исполнения сохранены. Терминальные команды не исключаются без проверки.
- Контроллер получает полную историю через внутренние неизменяемые строки; публичные снимки остаются независимыми изменяемыми копиями. Проверка новой команды и отображение используют компактный снимок, где история не нужна.
- Рассчитанная история закрытых позиций переиспользуется, пока не меняются сделки, открытые позиции и значимые подтверждения. Проверяется типочувствительный отпечаток полного содержимого, поэтому исправление строки без изменения длины, включая замену числа на bool, тоже обновляет историю. Отпечатки сериализуются только в памяти и никогда не десериализуются. Возвращаемые данные отделены от кеша.
- Карточки истории в панели перестраиваются только при изменении ревизии истории, а не на каждой котировке. Новая сессия получает отдельную ревизию.
- История не удаляется и не обрезается; долг RECOVERY, журнал и сохранение SQLite не сбрасываются. Полное сохранение состояния осталось прежним. Повторная глубокая копия неизменившегося подтверждённого состояния пропускается только после обычной успешной проверки и транзакции Store.save.

## Воспроизводимый замер

Из корня репозитория:

```sh
python3.13 tools/benchmark_paper_history.py "$PWD" --active --sizes 0,500,2000,5000
```

Это локальный синтетический тест полного `PaperSession.step`: завершённые STOP-команды с входной/выходной сделкой плюс действующая начальная позиция и три встречных ордера. Три измерения, медиана. MT5 не подключается. Это не замер пользовательского VPS.

Независимое сравнение с базой e323938 на одной машине:

| Завершённые команды | До | После |
| --- | ---: | ---: |
| 500 | 120 мс | 32 мс |
| 2000 | 1124 мс | 142 мс |
| 5000 | 6255 мс | 251 мс |

При 1000 командах текущий полный шаг занимает около 55 мс, при 5000 около 251 мс. Полный снимок и запись по-прежнему растут с объёмом истории: их стоимость остаётся линейной. Эти цифры не складываются напрямую в полный шаг и не являются гарантией задержки. Диагностика теперь отдельно показывает время снимка, сохранения, истории и представления.

В рабочем запуске представление панели публикуется раз в 0,5 секунды, а также при ожидающих командах и ошибках; обработка стратегии выполняется для каждой выборки независимо от частоты публикации. Замеры таблицы консервативно публикуют панель на каждом шаге.

Получение котировок вынесено отдельно, см. `PAPER_QUOTE_CAPTURE_RU.md`. Изоляция получения не делает медленный расчёт мгновенным: при длительном превышении скорости обработки очередь растёт, переполнение сообщает явную ошибку, а не молча пропускает наблюдения.

## Непрерывная нагрузка

Синтетический прогон 100 последовательных выборок с расписанием 0,1 секунды и публикацией панели раз в 0,5 секунды:

- 1000 исторических команд: медиана 42,8 мс, p95 64,3 мс, около 9,94 с на прогон, накопления отставания нет.
- 5000 исторических команд: медиана 257 мс, p95 373 мс, около 26,77 с; к концу отставание 16,77 с, что соответствует примерно 167 дополнительным поступлениям при непрерывном опросе.

Это оценка пропускной способности синтетического расписания, не испытание реальной очереди MT5 и не гарантия для Windows. При больших историях обработка всё ещё может уступать получению котировок. Панель показывает размер очереди; диагностика записывает её размер и отставание. После явной ошибки переполнения или отказа процесса стратегия не продолжает расчёт через неизвестный промежуток.

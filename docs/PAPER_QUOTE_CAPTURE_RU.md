# Независимое получение котировок PAPER

В рабочем запуске получение котировок выполняет отдельный процесс `spawn`.
Только он инициализирует MT5, читает данные, сверяет отображаемые часы и закрывает
подключение. Процесс стратегии не вызывает native MT5; сохранение SQLite,
обработка истории и веб-интерфейс не находятся внутри цикла получения цены.

По умолчанию запрос выполняется раз в 0,1 секунды (если сам вызов MT5 быстрее).
`quote_capture_interval_seconds` в конфигурации допускает 0,01–1 секунду.
Это **опрос наблюдаемых выборок**, не подписка на каждый брокерский тик.
Системная нагрузка, MT5 и скорость диска/процессора всё ещё ограничивают работу.
Нет обещания получить все тики между опросами.

Разные полученные цены передаются стратегии в порядке получения через FIFO.
Изменение цены в пределах одной миллисекунды не теряется; повтор одинаковой
цены/времени/закрытой свечи/спецификации не создаёт дополнительной выборки.
Каждая выборка содержит свою свечу и спецификацию: будущая свеча не подставляется
к более ранней цене. Интерфейс может показывать последнюю полученную цену, пока
стратегия обрабатывает очередь. `feed.capture` сообщает число полученных,
обработанных и ожидающих выборок; они не равны числу тиков у брокера.

Новые команды принимаются в очередь. Чтобы команда не исполнилась задним числом
по старой цене, её обработка производится после обработки выборок, полученных до принятия
команды, и наблюдения соответствующей границы получения. Более поздняя очередь
не обязана полностью опустеть: новые котировки не отодвигают команду бесконечно. Принятие команды не означает её исполнение. При устойчивой перегрузке
ожидание команды может увеличиваться; при этом новых ограничений по возрасту
котировки не вводится.

Очередь ограничена 4096 выборками, чтобы не занимать память без предела.
При переполнении получается явная ошибка `QUOTE_CAPTURE_OVERFLOW`: получение
и расчёт стратегии прекращаются, но панель остаётся доступной только для чтения
и показывает точную причину. Новые выборки не подменяют старые незаметно,
продолжение симуляции с неизвестным промежутком не выдаётся за корректный
результат. Необработанная часть очереди теряется явно, а не сохраняется для
восстановления. История сделок и долг остаются в базе. Это неисправность перегрузки,
а не стратегический SL или ручной порог RECOVERY. Очередь не является журналом
восстановления после падения: необработанные выборки при завершении процесса
не сохраняются; после перезапуска применяется прежняя модель текущей
наблюдаемой цены, без выдуманного восстановления промежуточных тиков.

Для завершения процессу даётся время закрыть MT5. Если native-вызов завис,
дочерний процесс принудительно завершается после ожидания; это не изменяет
торговые настройки MT5 и не посылает реальные ордера.

Проверки с искусственным источником запускают настоящий `spawn` и проверяют
очередность, отсутствие влияния занятого потребителя на получение, явное
переполнение, завершение, единственного владельца native-вызовов и очередь
ручных команд. Нативная интеграция Windows/MT5 требует отдельной проверки.
